# Бот очереди на сдачу лабораторных

Telegram-бот, который ведёт очереди на сдачу лабораторных по предметам с учётом подгрупп.

## Возможности

**Староста**
- `/creategroup` создаёт группу: название, число подгрупп, список участников. Каждому участнику бот выдаёт уникальный код для входа.
- Добавляет предметы: **общие** (одна очередь на всю группу) или **по подгруппам** (своя очередь у каждой подгруппы).
- Добавляет даты пар и рассылает **опрос** «будете сдавать?» группе или подгруппе. Видит, кто ответил «да», кто «нет» и кто не ответил.
- Редактирует очередь: двигает участников вверх и вниз, ставит на конкретное место, отмечает «сдал» или уважительную причину, добавляет, убирает, очищает очередь.
- Управляет участниками: добавляет, удаляет, выдаёт новый код (старый перестаёт работать).
- Удаляет группу целиком: участников, предметы, пары и очереди. Для подтверждения нужно ввести название группы, а участники получают уведомление.
- **Экспорт и импорт в Google Таблицы.** На каждую очередь создаётся отдельный лист. При импорте порядок из таблицы заменяет очередь в боте.

**Участник**
- Входит по коду: `/start` и код, или по ссылке `https://t.me/<бот>?start=КОД`.
- Смотрит актуальную очередь по любому предмету.
- Нажимает «Буду сдавать» и встаёт в конец очереди. Ответ «да» в опросе делает то же самое.
- Отменяет сдачу:
  - **до пары**: участник уходит из очереди;
  - **во время пары**: участник перемещается в конец очереди;
  - **во время пары по уважительной причине**: участник пишет причину, староста получает уведомление, а место сохраняется до следующей пары.
- Отмечает «Я сдал» и уходит из очереди.
- Предлагает **обмен местами** любому человеку из очереди, чтобы пойти раньше или позже. Обмен происходит, только если второй участник согласится.

**Автоматически**
- В начале пары всем участникам очереди приходит её актуальное состояние, а первому — сообщение «ваша очередь».
- Во время пары, когда первый сдал, ушёл в конец или отсутствует, следующему приходит «Подошла ваша очередь».
- После пары отметки об уважительной причине сбрасываются. Кто не успел сдать, остаётся в очереди на своём месте.

## Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Установите Python 3.11+ и зависимости:
   ```bash
   python -m venv .venv
   ```
   ```bash
   .venv\Scripts\pip install -r requirements.txt
   ```
   (на Linux/macOS: `.venv/bin/pip install -r requirements.txt`)
3. Скопируйте `.env.example` в `.env` и укажите `BOT_TOKEN`.
4. Запустите бота:
   ```bash
   .venv\Scripts\python -m bot
   ```

Бот работает через long polling, поэтому белый IP и домен не нужны. Данные хранятся в SQLite (`queue_bot.db`).

### На VPS через Docker
```bash
docker build -t queue-bot .
```
```bash
docker run -d --restart=always --name queue-bot --env-file .env -v "$(pwd)/data:/data" queue-bot
```
База и `credentials.json` лежат в папке `./data`.

## Google Таблицы (необязательно)

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект и включите **Google Sheets API** и **Google Drive API**.
2. Создайте **сервисный аккаунт**, затем на вкладке Keys выберите Add key → JSON. Сохраните файл как `credentials.json` рядом с ботом (или укажите путь в `GOOGLE_CREDENTIALS`).
3. Староста создаёт Google Таблицу и открывает к ней доступ **редактора** для email сервисного аккаунта. Бот покажет этот адрес в разделе «Google Таблицы».
4. Староста отправляет ссылку на таблицу в боте, после чего можно делать экспорт и импорт.

Формат листа: `№ | ФИО | Подгруппа | Уважительная причина`. Листы называются по предметам, например `Матан` или `Физика (подгруппа 2)`. При импорте участники находятся по ФИО без учёта регистра. Если ФИО не нашлось, бот сообщит об этом.

## Тесты

```bash
.venv\Scripts\python -m tests.test_flow
```
Тест прогоняет реальные хендлеры через Dispatcher с поддельным Telegram API: создание группы, вход по коду, запись, обмен, отмену во время пары, опросы, редактирование очереди и импорт/экспорт.

## Структура

```
bot/
  __main__.py       запуск
  config.py         настройки из .env
  db.py             схема SQLite и запросы
  queue_service.py  операции с очередью (под asyncio.Lock)
  services.py       отрисовка очереди, уведомления, опросы
  scheduler.py      начало и конец пар
  sheets.py         Google Таблицы
  handlers/
    common.py       /start, вход по коду, меню
    member.py       действия участника
    admin.py        функции старосты
    fallback.py     всё необработанное
```

## Ограничения
- Состояния диалогов (FSM) хранятся в памяти. Если перезапустить бота посреди ввода, ввод придётся начать заново. Сами данные лежат в SQLite и не теряются.
- Один Telegram-аккаунт может состоять только в одной группе.
